# Git 练习：改一份菜单

用几个文本文件体验分支、合并和回溯，预计 30～45 分钟。操作方式不限，命令行或图形界面都可以。

在 `F:\RM\git-playground` 新建独立仓库。若目录已经存在，换一个空目录。不要在真实项目里做，也不用上传远程仓库。

本文只给任务，不提供操作命令。不会的地方可以查资料。

## 任务 1：留一个起点

- 主分支叫 `main`。
- 新建 `menu.txt`，内容是 `drink=tea`。
- 完成第一次提交，给这个版本做一个方便以后找到的标记。

完成标准：工作区没有未提交的修改，能找到这次提交的编号。

## 任务 2：两条分支，各做一件事

- 从主分支创建 `add-dessert` 分支。
- 在新分支添加 `dessert.txt`，内容是 `dessert=cake`，并提交。
- 切回主分支，观察文件变化。
- 在主分支添加 `hours.txt`，内容是 `open=09:00-21:00`，并提交。
- 将甜点分支合并到主分支。

完成标准：主分支有三个文件；能展示两条分支分开、再合并的提交历史。

## 任务 3：故意制造冲突

- 从当前主分支创建 `change-drink` 分支。
- 在新分支把菜单中的饮料改成 `coffee`，并提交。
- 在主分支把同一行的饮料改成 `milk`，并提交。
- 尝试把 `change-drink` 合并到主分支，观察冲突。
- 自己决定最终菜单内容，解决冲突并完成合并。

完成标准：文件中没有冲突标记，工作区干净。记下你最终保留了什么，以及为什么。

## 任务 4：撤销一次错误提交

- 在主分支把饮料改成 `ink`，并提交。
- 撤销这次修改，恢复到任务 3 结束时的菜单。
- 要求保留错误提交的历史记录，并增加一条记录这次撤销的新提交。

完成标准：菜单恢复，错误提交和撤销记录都能在历史中找到。

## 任务 5：放弃尚未提交的修改

- 随意修改菜单，先不要暂存，也不要提交。
- 查看改动内容。
- 放弃这次修改。

完成标准：菜单恢复到修改前的内容，提交数量没有增加。

## 任务 6：去旧版本看看

- 将整个工作区切换到任务 1 的版本，观察文件内容和目录变化。
- 这一步只查看，不做新提交。
- 查看完后，回到主分支的最新版本。

完成标准：能在两个版本之间切换，且主分支的提交历史没有被改写。

## 任务 7：只取回一个旧文件

- 将主分支的菜单改成 `drink=water`，并提交，作为新的当前版本。
- 从任务 1 的版本中恢复 `menu.txt`，不要手动重写文件内容。
- 保留当前的甜点文件和营业时间文件。
- 将这次恢复作为一次新修改提交。

完成标准：菜单恢复成最初的茶，其他文件不变，主分支原有提交仍然保留。

## 任务 8：把提交弄丢，再找回来

这一项只在练习仓库做。开始前确认工作区干净。

- 从主分支创建 `recovery-practice` 分支。
- 新建 `note.txt`，写一句话并提交。
- 将这个分支退回到添加便签之前的提交，同时让工作区也恢复到那个版本。
- 观察便签文件和当前分支历史的变化。
- 从 Git 的本地操作记录中找到刚才的提交，将这个分支恢复到添加便签后的状态。不要靠重新创建文件或重新提交来完成。
- 最后切回主分支。

完成标准：找回的是原来那条提交，编号没有变化；主分支没有被这次回退和恢复影响。

## 最后留一份练习记录

保存在仓库外即可，几句话或几张截图都行：

- 一张能看出分支与合并关系的历史图。
- 冲突发生时的文件，以及你解决后的文件。
- 任务 4 和任务 8 对历史的影响有什么不同？
- 任务 6 和任务 7 分别改变了什么？
- 哪一步最容易操作错，下次准备怎样确认？

做完后保留这个小仓库，以后遇到不熟悉的 Git 操作，可以继续拿它试。
